# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Pipeline for refining small-object (vehicle) labels on aerial imagery (COWC, VEDAI) into YOLO-style Oriented Bounding Box (OBB) labels, using SAM plus a one-shot reference crop (`ref_car.png`). `VS_PerSAM_DINOv2.py` (VEDAI) downloads DINOv2 via `torch.hub`, which fails on analysis.jpl.nasa.gov (the proxy blocks github.com). `scripts/refine_labels.py` (README "Option 0: Run on any dataset") uses SAM encoder features by default and DINOv2 with `--features dino`, loaded from local, git-ignored files `models/dinov2-main/` and `models/dinov2_vits14_pretrain.pth` (see README). The repo is under development: Option 0 (`refine_labels.py`) is the preferred path and everything is meant to move over to it eventually; Option A (VEDAI study) is in progress; Option B (COWC) works but still runs the older `01cowc_persam_generate_dataset.py`. There is no build system, test suite, or linter — everything is a standalone script.

## Setup

- Python 3.10 in a conda env (conda-forge channel only): `conda create -n label-refiner python=3.10 -y && conda activate label-refiner && pip install -r requirements.txt`
- The repo doesn't use Git LFS (removed 2026-10-20; no LFS files were tracked). Model weights (`*.pth`) are git-ignored, so don't commit large binaries.
- `.gitignore` ignores `data/`, `datasets/` and anything matching `*dataset*` (so every `mini_dataset*` folder). The mini test sets are reproduced from checked-in lists instead: `COWC_mini_test/image_list.txt` (`scripts/make_cowc_subset.py`) and `VEDAI_mini_test/image_list.txt` (`scripts/make_vedai_subset.py`).
- Raw data (`data/COWC`, `data/VEDAI`) is not in the repo; it is downloaded from a Google Drive link in README.md and unpacked per the README's commands.
- `Personalize-SAM/` is a vendored copy of the PerSAM project (own README/requirements); the `scripts/` code imports `segment_anything` (pip package), not `per_segment_anything`.

## Running

**Always run from the repo root** — scripts use relative paths (`data/`, `datasets/`, `datasets_refined/`, `models/sam_vit_b.pth`) and create output dirs themselves. Paths and parameters are mostly hardcoded as constants at the top of each script; edit them in place. Exception: `refine_labels.py` (Option 0) takes CLI options (`--input`, `--output`, `--ref`, `--ref-tile`, `--box-prompt`, `--features sam|dino`, `--snap`, `--negative`, `--sim-margin`, ...; see README "Option 0") and accepts either a flat `images/`+`labels/` dir or a `train|val|test/{images,labels}` dir, mirroring the layout in its output (`data.yaml` only for the split layout). Example: `python scripts/refine_labels.py --input COWC_mini_test/mini_dataset --output COWC_mini_test/mini_dataset_refined --ref datasets/COWC_Points_512/ref_car.png`. The older `01cowc_persam_generate_dataset.py` is kept as is (no CLI; hardcoded `datasets/` paths, Otsu reference mask, plain 5-point prompt, no report CSV) until Option B is migrated to `refine_labels.py`; don't add features to it. Plot OBB labels over images with `data_exploration/plot_obb_labels.py`, and compare runs side by side with `data_exploration/compare_plots_html.py` (static page, auto-reloads; README covers viewing it over an SSH tunnel). Use the `label-refiner` conda env; on analysis.jpl.nasa.gov CUDA is unusable (driver too old), so SAM runs on CPU at about 3 s per 512px tile.

Option A (VEDAI, superseded by Option 0 except its converter): `python scripts/VS_VEDAI_Separation_Conversion.py` → `python scripts/VS_PerSAM_DINOv2.py` → `python scripts/VS_evaluate_pipeline.py` (results land in `visuals/vedai_*_evaluation_results/`). Defaults to the color (RGB) dataset. Don't extend the last two; `VS_evaluate_pipeline.py` treats class 2 (truck) as a target.

VEDAI tuning (README "Tuning on VEDAI"): `VS_VEDAI_Separation_Conversion.py` keeps car/van/pickup (VEDAI classes 1, 9, 11) with a 21x9 px placeholder box → `scripts/make_vedai_subset.py` (builds `<dir>/mini_dataset` + `<dir>/truth/labels` from the tune split, never the fold01test holdout; `VEDAI_mini_test/image_list.txt` is the 12-image check set) → `bash scripts/run_vedai_sweep.sh` (settings list at its top, `--car-length 21`, `V=<dir>` for another set, skips finished runs) → `python scripts/summarize_vedai_sweep.py` (sweep_summary.txt + mini_compare.html). Anything named `*dataset*` is git-ignored, so subsets must be rebuildable from a list file. `make_vedai_subset.py --jitter-length 3 --jitter-width 1` moves the input points up to 3 px along / 1 px across each vehicle (truth unchanged) to simulate hand-clicked labels (`--jitter R`, any direction, was the earlier 4 px study); `SWEEP=jitter` selects the snap/DINOv2 settings, and `scripts/run_vedai_jitter_overnight.sh` runs them on the exact-point and jittered sets in parallel. `make_vedai_subset.py --holdout` builds the fold01 holdout set (`VEDAI_holdout`, plus `_jitterL3W1`) for `SWEEP=holdout` final checks only. `data_exploration/vehicle_crops_html.py` shows zoomed per-vehicle crops, one column per run.

Option 0 (any dataset): prepare `images/`+`labels/` point labels (for COWC, `python scripts/00pure_geographic_splitter.py`) → `python scripts/refine_labels.py ...` → `data_exploration/plot_obb_labels.py` → `data_exploration/compare_plots_html.py`.

Option B (COWC; its refinement step is superseded by Option 0, but degradation/validation have no Option 0 equivalent yet): `python scripts/00pure_geographic_splitter.py` → `python scripts/01cowc_persam_generate_dataset.py` → `python scripts/02sensor_degradation.py` → `python data_exploration/val_yolo_dataset.py`.

## Architecture

Stages hand off through directories:

1. `data/` (raw) → **splitter/converter** scripts (`00*`, `VS_VEDAI_Separation_Conversion.py`) tile into 512x512 patches (stride 256) with geographic train/val/test splits, producing point-style (center-point) YOLO labels in `datasets/COWC_Points_512/`.
2. **Refinement** (`refine_labels.py`, the older `01cowc_persam_generate_dataset.py`, `VS_PerSAM_DINOv2.py`): loads SAM ViT-B, computes a target feature vector from a reference, prompts SAM at each labeled point, converts masks to 4-point OBBs via `cv2.minAreaRect`, then applies geometric filtering (reject boxes with max dimension >90 px or <6 px, duplicates by IoU, etc.). Writes to `datasets_refined/COWC_512/` with `data.yaml`.

   In `refine_labels.py` the reference only affects the per-box `refinement_report.csv` flags (cosine similarity vs. the image's median), not the label geometry, unless `--snap`/`--negative` are passed; both are off by default because they reduced accepted SAM masks on the mini dataset. `--box-prompt` (box + ring of negatives, from the VS script, but keeping fallback boxes rather than dropping cars) is the biggest improvement found so far: 54/65 accepted masks vs 24. DINOv2 features only separate cars from background with a reference *tile*; with the padded `ref_car.png` crop they don't (they depend on context), whereas SAM features work with either. The reference must match the dataset's scale: an upscaled `ref_car.png` is shrunk back automatically (pixel-block detection) and padded onto a 512 canvas, and its mask comes from SAM. Never use Otsu masks for the reference — on COWC they came out inverted (pavement marked as car). All size thresholds are in pixels, tuned for COWC (~30px cars), and in `refine_labels.py` go through `px()`, which scales them by `--car-length` / 30 (use `--car-length 21` for VEDAI 512); wrap any new pixel threshold in `px()`. `scripts/evaluate_updated_vedai_labels.py` scores a `refine_labels.py` run on `datasets/vedai_512/vedai_color_centerpoint` against the true VEDAI car OBBs, with VEDAI's `fold01test.txt` as the holdout set (`--split tune` while tuning, `--split holdout` only for final checks). `mask_to_yolo_obb` and `load_sam` are duplicated across `refine_labels.py`, `01cowc_persam_generate_dataset.py` and the VEDAI script (`geometric_correction_head` too, in the first two) — keep them in sync if changing one.
3. `02sensor_degradation.py` applies sensor artifacts/resolution degradation to build a degraded copy of the dataset.
4. `data_exploration/` holds interactive inspection/QA tools (OpenCV-based; `val_yolo_dataset.py` uses A/D to navigate and M to flag bad images; the split being validated is set in a config at the top of the file). Others produce the visuals in `visuals/`.

`VS_*` scripts are the VEDAI study (DINOv2 → SAM relabeling and precision/recall evaluation); un-prefixed numbered scripts are the COWC path.
